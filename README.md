## 它做什么

把一段中文访谈录音，在本机变成一份带说话人、带时间戳、标了存疑处的转录稿。

单台开源 ASR 转中文访谈，错得比你想象的多。这个项目的做法是让**四台解码路线互不相同**的引擎
听同一段音频，用代码穷举定位它们写法不一致的地方，再交给一个大模型逐处定字 —— 定不下来的就地标 `[❓]`，
留给你复核。

```
音频
 └─ 声纹分段（pyannote-segmentation-3.0 + CAM++）+ VAD 补漏 → 18 秒切块
     │
     ├─ FireRed-ASR2      AED 自回归
     ├─ Zipformer-CTC     CTC 逐帧          四路吃同一份切块，
     ├─ Paraformer-2023   非自回归          块与块天然逐一对应
     └─ Qwen3-ASR 0.6B    LLM 式
     │
     ├─ 分歧册 —— 纯 Python 穷举定位各路写法不一致的片段
     └─ 融合 —— 大模型按规则 + 你的术语库定字
     │
   融合终稿
```

## 它做得怎么样

我们拿一条 **37 分 51 秒的真实客户访谈**（人工整理稿作金标）量过。口径是
461 个实质语义块里出问题（漏或错）的块数：

| | 出问题的块 |
|---|---|
| 最好的单台本地引擎（FireRed-ASR2） | 56 |
| **本地四路 + 融合** | **24** |
| 四路组合的理论天花板（四台都听错的） | 19 |

可拿回的空间是 `56 − 19 = 37 处`，实际拿回 32 处（86%），**零回退** —— 没有出现「单台本来对、融合改错」的情况。

**它离商用还有多远，我们也说：** 同一条录音走我们自己的云端生产线，残留不到 10 处，
而且那些残留在流程里都留了痕、都能由人工复核改掉。要 27 门语言、更高精度或团队协作，
用[在线版](https://transcribe.solutions)。

**24 处里有 16 处是四路一起听错的** —— 正确写法根本不在选票上，换更强的融合模型也投不出来。
这 16 处里 **10 处是术语**（光伏行业的专名与行话）。所以术语库是最值得先挂的东西，
但它只在**库里真有那个词**时才起作用：我们拿现成的客户术语库对过，那 10 个词**一个都不在库里**。
术语库要写对才有用，不是挂上就有用。

> 上面这些数字用的是我们内部的完整融合提示词。仓库里这份是**简化版**，成绩会有出入，
> 发布前会用简化版重跑一次全长并把数字更新到这里。

## 装

尚未发布。

模型约 **2.8 GB**（四路 ASR + 声纹），从各自官方源下载，**本仓库不重分发权重**。
想全本地跑融合的话，再加一个本地大模型（Qwen3-8B-4bit 约 4.6 GB）；也可以把融合接到任何
说 OpenAI 协议的 API 上，改一个 `base_url` 就行。

## 调

这个软件的正题是**参数可调**，而且每个参数都告诉你「这个默认值是怎么来的」：

```
[定档]     有全长实测支撑
[未验证]   照搬上游或凭常识定的，没有实测证据
[有更好的] 已经量出更好的做法，但还没落地
[缺陷]     已知有问题，尚未修
```

全部参数见 [`config.default.yaml`](config.default.yaml)。已知缺陷也在里面明写，没有藏着。
