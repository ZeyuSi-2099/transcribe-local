# 怎么复现那些数字

README 里的成绩来自一条 **37 分 51 秒的真实客户访谈**，人工整理稿作金标。
那条录音和金标**不在这个仓库里**，也不会公开 —— 是客户内容。所以这一页讲的是**口径**，
让你能用自己的素材量出可比的数字。

## 口径

1. **切语义块。** 金标按 `。？！` 断句，过长的单元再按 `，、；：` 切到约 32 字。
   那条录音切出 **665 个语义块**。
2. **扣掉纯附和块。** 「嗯」「对」「是的」这类不承载内容的块不计分 —— 那条录音有 **204 个**（31%）。
   剩下 **461 个实质块**是分母。
3. **逐块判定。** 只数两种：
   - **漏**：内容实质上没出来。
   - **错**：写成了另一个意思的东西。
4. **五条不算错**（口径 2026-09-11 定，按这五条过一遍，过不去的才算问题）：

   | | 不算问题 | 例 |
   |---|---|---|
   | ① | 只差语气词 / 附和词 / 儿化 | 金`哦，明白` 机`明白` |
   | ② | 数字体例不同 | 金`23 年 12 月 28 号` 机`二三年十二月二十八号` |
   | ③ | 的地得 / 您你 | 金`频繁地报警` 机`频繁的报警` |
   | ④ | 机器自己标了 `[❓]` | 它举手说了「这儿我没把握」 |
   | ⑤ | 机器写的是术语库里的词形、金标记的是同字不同序的口语说法 | 只认「字完全一样、只是顺序不同」，不认近义替换 |

   归一（抹掉 ①②③）之后，**金标那句必须原样出现在机器稿里**才算过。

   > ⚠️ **别用相似度阈值。** 我们第一版用 0.88，结果一个两字术语被听成同音单字、
   > 夹在三十多字的长句里，整句相似度仍有 0.9+，被判成「一致」放过了。
   > 相似度阈值会让自家产品看起来比实际好。
5. **按文字对齐，不按时间轴。** 人工金标的时间戳只到秒，按时间轴打分会把 1 秒偏差误判成整句错
   —— 同一份数据，时间轴口径 81%，文字对齐口径 99.7%。判某段归谁，**拿文字回金标原文搜出处**。

成绩 = 出问题的实质块数。**不报百分比** —— 分母口径一变百分比就不可比，绝对块数更诚实。

## 组合天花板

单台的成绩没什么意思，要看的是组合：**461 个实质块里，「四台全都坏」的还剩几个。**
那是任何融合方案都赢不过的下界。

那条录音上（每一档都取该台数下最好的那个组合）：

```
1 台   95    FireRed-ASR2
2 台   62    + Zipformer-CTC        ← 第二台拿掉 33 处，价值最大
3 台   52    + Qwen3-ASR              第三台再拿 10 处
4 台   48    + Paraformer-2023        第四台只再拿 4 处   ← 天花板
```

**边际收益掉得很快**：第二台顶半边天，第四台几乎白搭 —— 加引擎不是越多越好。
我们仍然默认四台，是因为那 4 处里有内容，而多跑两台的代价只是时间。

所以**评价融合的指标是「95−48=47 处的可拿回空间里，拿回了几处」**，不是绝对分数。
实测融合拿到 54，也就是拿回了 41 处、离天花板还差 6 处。

这些数全部由 [`tools/score.py`](../tools/score.py) 算出，你可以用自己的素材复现。

## 两个会让你得出错误结论的坑

**① 5 分钟窗口测不出融合质量。** 全长可拿回 37 处，但任意一个 5 分钟窗口只有 0–5 处
（前 5 分钟仅 2 处、35–40 分钟为 0）。短窗口只能验管道跑不跑得通，**打分必须跑全长**。

**② 同一秒挂多行是正规转录惯例，不是错。** 那条录音 462 行里有 254 行（55%）与相邻行共用时间戳；
461 次换人里有 129 次落在这种零时长的轮次上。

## 想复现引擎横评

横评那 192 块是用**旧的声纹门槛 0.15 / 0.20** 切的（现在的默认值是 0.05 / 0.10，召回更好）。
要对比横评成绩，得把 `config.default.yaml` 里的 `diarize.min_duration_on/off` 改回旧值。

这一条是真实的历史包袱，不是故意的 —— 门槛是在横评之后才定下来的。
