# 术语库怎么写

术语库是一个文本文件，一行一条，格式：

```
- 术语 ｜ 一句话含义
```

中间是**全角竖线** `｜`（不是半角 `|`）。含义写给模型看，一句话就够。同一个词的几种正确写法用 `/` 隔开写在左边。

融合定字时它会整份内联进提示词，命中即作硬证据。挂法：命令行 `--terms 你的库.md`，或配置 `terms.files`，或界面「术语库」页。

## 三条规矩

1. **只收正确写法，别把常见的错写也列进去。** 模型会把库里的词当权威照着改；写错的词形会被当成正确答案，比不写更坏。
2. **收不收，看这一条：它被听错时，这句话会不会变成另一个意思。** 会，就收；不会，就别收，哪怕它看起来再专业。换一家同行还会不会冒出这个词？会，多半是大路货，别收；不会，才是这一家自己的说法。
3. **改了库，跑三遍看平均，别看一遍。** 融合那一步每次结果都不一样；库有没有帮上忙，一次跑不出来。

## 它能做什么、不能做什么

- 能：某一路引擎已经给出了**读音相近的残片**时，库告诉模型那个词该怎么写。
- 不能：四路引擎都没听出一点音近的东西时，库变不出正确答案；模型会标 `[❓]` 交给你。
- 不保证：库里有这个词，也不保证每一处都写对。它提高的是概率，不是承诺。

## 检查一下

```bash
python3 tools/terms_check.py 你的库.md
```

它查格式、重复、以及疑似把错写形收进来的条目（左边的词跟某一路引擎的原始输出逐字相同、却与其他条目冲突的，会提醒你看一眼）。
